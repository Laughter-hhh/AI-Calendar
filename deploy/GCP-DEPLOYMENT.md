# 部署指南：Google Cloud 免费服务器（Compute Engine）

把 AI Calendar 部署到 Google Cloud 的永久免费虚拟机（e2-micro），适合海外用户小范围测试。以下内容和限制说明基于 Google 官方文档（2026-08 核实）。

## 0. 先看结论：免费额度和限制

Google 提供两套免费机制，容易混淆，先说清楚：

| 项目 | 说明 |
|---|---|
| **新用户试用额度** | $300 美元额度，**90 天**有效；90 天后未用完的部分作废 |
| **永久免费层（Always Free）** | **没有到期时间**，按月重置用量，只要不超限就一直免费 |
| 免费虚拟机 | 1 台 e2-micro（**1GB 内存、共享 CPU**），每月免费，但**只能建在北美三个区域**：us-west1（俄勒冈）、us-central1（爱荷华）、us-east1（南卡罗来纳） |
| 免费磁盘 | 30GB **标准**持久磁盘（注意：默认的 balanced 磁盘不在免费范围内） |
| 免费流量 | 每月 **1GB 出站流量**，且**只限北美出发、目的地不含中国大陆和澳大利亚** |
| 免费快照 | 每月 5GB 快照存储（可用于备份数据库） |

**超限后果**：超过免费范围的部分按标准价格从信用卡扣费。所以第 6 步的“预算提醒”一定要做。

### ⚠️ 两个必须提前知道的问题

1. **中国大陆访问 Google Cloud 不稳定**（Google 服务在大陆通常无法直接访问）。如果你的测试用户主要在国内，这条路很可能打不开。**此时更推荐原本的国内云服务器方案**（见 DEPLOYMENT.md），或者用本机+内网穿透先顶着。
2. **注册需要国际信用卡**（Visa/Mastercard 等），注册时会冻结一笔小额验证款并退回；同时需要能访问 Google 的网络环境。

---

## 1. 注册账号

1. 打开 https://cloud.google.com ，用 Google 账号登录
2. 点击「免费开始 / Start free」，按提示填写信息并绑定国际信用卡（验证小额扣款会退回）
3. 注册成功后自动获得 $300 试用额度（90 天）
4. 首次使用 Compute Engine 时，控制台会提示启用 Compute Engine API，点「启用」即可

## 2. 创建虚拟机（注意几个防收费选项）

控制台 → Compute Engine → 虚拟机实例 → 创建实例：

| 选项 | 填什么 | 注意 |
|---|---|---|
| 名称 | `ai-calendar` | 随意 |
| 区域 | **us-west1**（对亚洲延迟最好） | 只有 us-west1 / us-central1 / us-east1 免费 |
| 可用区 | 默认即可 | |
| 机器类型 | **e2-micro** | 免费层指定机型，选别的会收费 |
| 启动磁盘 | Ubuntu 22.04 LTS x86 | |
| 磁盘类型 | **标准持久磁盘（pd-standard）** | 默认可能是 balanced，**务必改成标准** |
| 磁盘大小 | 30GB | 免费上限 |
| 网络层级 | 标准（Standard） | 可选，能省一点流量费 |
| 防火墙 | 先不勾选 HTTP/HTTPS（我们用 3000 端口，下一步单独放行） | |

创建完成。如果担心误建付费资源，创建后留意页面右上角是否显示费用估算为 $0.00。

## 3. 放行 3000 端口

GCP 的防火墙和服务器内部防火墙是分开的，必须在这里放行：

控制台 → VPC 网络 → 防火墙 → 创建防火墙规则：

- 名称：`allow-ai-calendar-3000`
- 目标：全部实例（或 `tags` 指定）
- 来源 IPv4 范围：`0.0.0.0/0`
- 协议和端口：**指定的协议和端口 → TCP → `3000`**
- 操作：允许

## 4. 登录服务器并一键部署

1. 在虚拟机列表找到实例，点行尾的 **SSH** 按钮（浏览器内直接打开终端，不用配置密钥）
2. 在 SSH 终端里粘贴以下命令（把仓库地址换成你的）：

```bash
sudo apt-get update -y && sudo apt-get install -y git
git clone -b main https://github.com/你的账号/AI-Calendar.git /tmp/aical
```

3. 海外服务器上，用官方源更快（Google 服务器访问 npmmirror 不一定快）：

```bash
sudo NODE_MIRROR=https://nodejs.org/dist NPM_MIRROR=https://registry.npmjs.org \
  bash /tmp/aical/deploy/server-setup.sh https://github.com/你的账号/AI-Calendar.git main
```

脚本会自动：装 Node.js → 装 pnpm/pm2 → 拉代码 → 构建 → 用 pm2 启动在 3000 端口 → 自动开 1G swap（e2-micro 内存小，防止构建失败）。

> e2-micro 构建较慢（可能 5~15 分钟），耐心等“部署完成”字样。

## 5. 验证

1. 在 SSH 终端执行：`curl http://localhost:3000/api/health`，返回 `{"ok":true,...}` 即正常
2. 回到本机浏览器，打开 `http://虚拟机公网IP:3000`，注册账号测试
3. 公网 IP 在虚拟机列表里能看到（外部 IP 列）

> 临时 IP 在**停机再开机后可能变化**。免费层建议让虚拟机保持运行（一直免费）；如果 IP 变了，把新地址重新发给测试者即可。

## 6. 设置预算提醒（防超支，必做）

控制台 → 结算（Billing）→ 预算和提醒（Budgets & alerts）→ 创建预算：

- 金额：设一个很小值，如 `$2`
- 提醒阈值：50%、90%、100%（选邮件通知）

只要接近或超出，Google 会发邮件提醒，避免不小心用了付费资源。

## 7. 日常运维

```bash
# 看日志 / 重启 / 停止
pm2 logs ai-calendar
pm2 restart ai-calendar

# 更新代码（本机 git push 之后）
cd /opt/ai-calendar
git pull
cd frontend
pnpm install
pnpm build
pm2 restart ai-calendar

# 备份数据库（重要）
cp /opt/ai-calendar/database/data/ai-calendar.db ~/ai-calendar-backup-$(date +%F).db
```

也可以到控制台用「快照」备份整台机器（免费额度内 5GB）。

## 8. 限制对后续开发的考量

这是你要求纳入后续规划的部分，按重要程度排列：

1. **1GB/月出站流量是最大的硬限制**，且大陆流量不计入。当前页面首访约 300~400KB、重复访问约 20KB，1GB 大约够几十个测试用户高频使用一个月。后续优化方向：保持前端轻量（少放大图、少引第三方脚本）、打开服务端压缩。如果流量要长期增长，就必须考虑升级或换方案。
2. **中国大陆访问不可靠**：如果产品定位是国内用户，这个免费服务器只能用于“海外朋友测试”。国内正式测试要回到国内云方案。
3. **e2-micro 性能有限（1GB 内存）**：当前 SQLite 单文件 + Next.js 是匹配的；不要在服务器上跑多余服务（数据库、队列等都别装）。
4. **90 天试用结束后**：免费层继续有效，但任何超限都会扣费，所以预算提醒必须常开。
5. **未来迁移路径**：如果以后想用 Google 的 Cloud Run（也有免费额度：每月 200 万次请求），需要先解决“SQLite 存不进临时磁盘”的问题——届时把数据层换成外部数据库即可，这也是产品文档里 PostgreSQL 路线的由来。

## 常见问题

| 现象 | 解决办法 |
|---|---|
| 外网打不开，服务器上 curl 正常 | 检查第 3 步的防火墙规则是否创建、目标是否包含该实例 |
| 页面提示费用不是 $0 | 检查区域是否在三个免费区、磁盘是否标准型、是否多建了实例 |
| 想用自己的域名 | 域名解析 A 记录到公网 IP，后续再加 HTTPS（免费证书） |
| 忘记密码 | GCP 网页 SSH 不需要密码；密钥丢了可在控制台重置 |
