# AI Calendar 路线图：待拓展功能与待确认项

> 本文档记录**下一步要做什么**（有明确技术方案）和**需要用户/产品方拍板的事**。新 AI 智能体接手时，从这里挑选下一个任务，并在完成后更新本文档。

## A. 待确认项（需要用户决定，阻塞后续开发）

| # | 事项 | 影响 | 现状 |
|---|---|---|---|
| 1 | **域名 + ICP 备案**：是否购买域名并走备案（约 1~2 周） | 决定能否用域名访问、上 HTTPS（App 正式打包的前提） | 当前用 IP+端口 |
| 2 | **真实 AI Key**：是否配置 `OPENAI_API_KEY` | 解析能力从"规则版"升级为"模型版" | 未配置，本地解析器兜底 |
| 3 | **重复事件系列编辑语义**：修改/删除"这一个"还是"整个系列" | 决定重复事件 UI 交互设计 | 当前只支持单事件编辑 |
| 4 | **App 方向**：WebView 壳 vs 原生界面；是否上架应用商店 | 决定 mobile/ 的投入方向 | WebView 壳已可用 |
| 5 | **数据迁移路线**：SQLite → PostgreSQL 的时机（V3 多用户时） | 决定多用户/云同步方案 | SQLite 单文件，够小范围用 |
| 6 | **语音识别服务**：浏览器 Web Speech API（免费但依赖浏览器）vs 付费语音服务 | 语音体验稳定性 | 浏览器内置实现，Chrome/Edge 可用 |

## B. 待拓展功能（技术方案已明确，按优先级排序）

### B1. 重复事件：系列编辑（下一个大项）

- 现状：v2.0.0 已支持 daily/weekly/monthly 的查询期展开和"仅删除本日"；v2.1.0 支持自然语言修改/删除（整个系列）
- 待做：
  - 事件卡片显示"这是重复系列"标识 + 「编辑此日 / 编辑整个系列」两个入口
  - 系列编辑：修改 base 事件（标题/时间/规则），历史已过去的日子不回写
  - 系列删除：删整个系列（按 base id 删除）或仅删当日
  - 需要按待确认项 #3 拍板语义

### B2. 周视图 / 月视图

- 现状：单日 / 未来 7 天 / **月视图**（v3.0.0 / v3.1.0）；区间查询已就绪
- 待做：月视图内直接创建/编辑（点击空白格创建）；拖动调整时间

### B3. AI 能力增强

- 追问记忆：当前追问只带一次上下文，可升级为会话内多轮记忆（产品文档 MVP 不存聊天历史，V2 可放开）
- 批量意图：一次输入多件事（"下午开会，晚上健身"）
- 冲突检测：新建日程与已有日程时间重叠时提示

### B3.5 日历互通与展示增强（参照主流日历应用）

- 现状（v3.1.0）：ICS 导出、搜索、事件详情/备注、增强编辑、今日下一项
- 待做：ICS 导入；事件颜色/分类标签；农历显示；暗色模式；日历订阅（URL 只读日历）

### B4. 数据安全与运维

- 定时自动备份数据库到本地/对象存储（备份脚本已就绪：`scripts/backup.sh`，待服务器上配置 cron）
- 服务器监控：uptime/磁盘/进程自动告警（可接阿里云监控，免费）
- 数据库健康检查并入 `/api/health`（v3.0.0 已加 DB 探测 ✅）

### B5. PWA（需要先有 HTTPS）

- 依赖待确认项 #1（HTTPS）。之后补 manifest + service worker + 图标即可让网页"可安装为应用"

### B6. 用户反馈系统（V3）

- 产品文档 V3 内容：站内反馈入口 + 反馈存储（复用 events 表思路或新建 feedback 表）

### B7. 多用户与云端同步（V3）

- 当前为单库多用户（按 user_id 隔离），架构上已具备；云端同步=换 PostgreSQL + 跨设备数据合并策略

## C. 已完成功能的历史（详见 docs/versions/）

- v1.0.0：注册登录、自然语言建日程、连续 N 天、追问、语音、按日期查看、编辑删除、CI 部署、手机 App 壳
- v2.0.0：完整重复事件（每天/每周/每月 + 截止日期 + 查询期展开 + 仅本日删除）
- v2.1.0：AI 修改/删除日程（"把 X 改到 Y" / "删除 X"）
- v3.0.0：未来 7 天概览、区间查询、备份脚本、API 文档、健康检查含数据库探测
- v3.1.0：月视图、事件详情与备注、增强编辑、搜索、ICS 导出、今日下一项提示
