# 发布测试数据规范

每次修改进入发布流程后，必须先在隔离数据库中生成一组可追踪、可验证、可清理的测试数据。测试数据通过后才允许打包、上传和重启服务器。

## 数据隔离

- CI 必须设置独立的 `DATABASE_PATH`；禁止连接 `/opt/ai-calendar/database/data/ai-calendar.db` 或任何生产地址。
- 测试账号使用 `ci-<run-id>-<timestamp>@test.local`，每次运行唯一。
- 事件标题使用 `[CI-<run-id>]` 前缀，不使用生产用户的固定 ID、事件 ID 或真实个人信息。
- 生成器失败或进程异常时仍尝试清理已创建的事件和笔记；CI 临时数据库在任务结束后由运行器销毁。

## 必测样本

生成器 `scripts/generate-test-data.mjs` 每次运行必须覆盖：

1. 单条定时事件（含开始/结束时间）；
2. 12:00–14:00 与 13:00–14:00 的重叠事件，并验证冲突提示；
3. 全天待办；
4. 带截止日期的每日重复事件；
5. “本周三 / 本周四”两条独立的一次性事件，验证 `repeat === null`；
6. 一条笔记，并验证可查询。

生成后必须查询区间，确认所有事件存在、一次性语义未被改写，再执行清理。导入、编辑、删除、离线和布局等专门场景由其对应回归脚本继续覆盖。

## 自动上线门禁

GitHub Actions 的顺序固定为：冻结锁文件安装 → ESLint → production build → 临时数据库启动 → 测试数据生成与校验 → 全套回归测试 → 打包上传 → 服务器健康检查。任一步失败都不得部署；服务器启动或健康检查失败时保留并恢复上一版本。

本地只需使用同一套命令复现：

```bash
DATABASE_PATH=./.tmp/ci.db BASE_URL=http://127.0.0.1:3100 node scripts/generate-test-data.mjs
```
